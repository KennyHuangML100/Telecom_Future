Question 1:

題目一：AI-RAN 的豪賭——要當「智慧大腦」還是「純搬運工」？

Nvidia 近期入股 Nokia 並全力推動 AI-RAN（AI 無線存取網路），主張將基站轉化為分散式 AI 中心，讓電信設備不只負責傳輸（Connectivity），更能邊緣運算（Inference）。

衝突點： 擁抱 AI-RAN 意味著必須大幅汰換現有架構，並在資本支出（CAPEX）高漲的當下，再次投入巨額預算給 Nokia / Nvidia「繳保護費」；但不擁抱，則可能在未來邊緣 AI 戰場中徹底失去話語權。

請解題： 如果你是台灣大哥大的技術長（CTO），你會如何評估這項投資？請利用第一性原理分析：電信商究竟要堅守「平價穩定的傳輸」，還是要挑戰「無處不在的算力」？

-----------------------------------------------------------------------------------------------------------

Suggestion 1:

如果我是台灣大哥大 CTO，我的結論會是：

**不把 AI-RAN 當成下一輪「全面換基站」的宗教戰爭，而把它當成一個有選擇權價值的邊緣算力實驗。核心網路繼續守住低成本、高穩定、高覆蓋；AI-RAN 只在能產生明確企業收入或網路效率收益的場景中分區部署。**

Nvidia 入股 Nokia 這件事確實代表產業方向轉強：Nvidia 以約 10 億美元取得 Nokia 約 2.9% 股權，雙方主軸是把 Nokia RAN 軟體適配到 Nvidia AI/RAN 平台，推動 5G-Advanced/6G 的 AI-RAN 架構。Nokia 官方也把這描述為從「5G 到 6G」之外的網路重設計，把 AI 處理能力推向邊緣。([金融時報][1]) 但這仍在早期商用化階段；Nokia/Indosat 已完成 AI-RAN Layer 3 5G call，Nokia 也說 2026 會有首批商用 trial、2027 才有商用 release。([Mobile World Live][2])

## 第一性原理：電信商賣的不是「技術」，而是「可靠稀缺資源」

電信商的基本產品其實只有三個：**覆蓋、容量、低延遲可信連線**。消費者不願意為「我的基地台裡有 GPU」多付月租；企業也不會為 AI-RAN 本身買單，只會為「更低停機風險、更低延遲、更高資料主權、更便宜的現場自動化」買單。

所以問題不是「要不要擁抱 AI-RAN」，而是：

**把 AI 算力放進 RAN，能不能比放在區域資料中心、公有雲、企業私有邊緣機房更便宜、更穩、更可收費？**

大部分情境下，答案目前不是。因為 AI-RAN 會同時增加設備成本、功耗、散熱、維運複雜度、供應商鎖定風險，還可能讓本來應該高度確定性的 RAN 承擔 AI workload 的波動性。電信網路的第一原則是「五個九的穩定」，AI workload 的第一原則是「高利用率與快速迭代」。兩者天然衝突。

但在少數場景，答案可能是。尤其是延遲、資料在地性、無法上雲、需要和 5G 專網/切片深度整合的場景，例如智慧工廠視覺檢測、港口/機場機器人、醫療院區即時影像、國防/公共安全、車聯網路側感知。這些地方的算力不是「無處不在」，而是「放在正確的 20 個熱點」。

## 對台灣大哥大的現實判斷：不能 all-in，也不能缺席

台灣大哥大現在不是一張白紙。它已經在講 Telco+Tech、AI、資安、雲端與企業服務；公司 2025 年提出企業服務 6C 策略，包含 telecom、cloud and AI、consulting/managed services、cybersecurity、carbon/energy management、application integration。([台灣大哥大][3]) 同時，台灣大 2025 年財報訊息顯示現金股利維持高配息，且 2Q25 自由現金流受惠於較低 capex。([台灣大哥大][4]) Fitch 也指出台灣 5G 建設週期已過高峰，預期電信 capex 會逐步下降。([Fitch Ratings][5])

這意味著，若現在突然大規模換成 Nokia/Nvidia AI-RAN，會逆著資本市場對電信商的期待：**5G 投資高峰後，投資人要的是現金流、整併綜效、ARPU 提升，而不是再來一輪看不到回收期的基站軍備競賽。**

所以作為 CTO，我會把 AI-RAN 分成三層：

第一層是**不用 AI-RAN 也該做的事**：RAN energy saving、SON、自動化維運、異常偵測、容量預測。這些可以用 AI，但不需要把每個基站變成 GPU 節點。

第二層是**區域邊緣 AI**：在台北、新北、桃園、新竹、台中、高雄等都會核心節點建立 telco edge AI pool，靠 MEC、5G SA、切片、資安與企業 SLA 收費。這比每站 AI-RAN 更務實。

第三層才是**真正 AI-RAN**：只在企業專網、園區、港口、製造業聚落、體育場館或特殊低延遲場景導入 Nokia/Nvidia 試點。目標不是炫技，而是驗證三個數字：每瓦推論成本、每站新增收入、對 RAN KPI 的改善。

## 我的投資原則：把它當「期權」，不是「主航道」

我會設定一個很硬的投資門檻：

**AI-RAN 不能只用 6G 敘事 justify，必須在 18–24 個月內證明至少一種可量化收益。**

收益可以來自三個方向：

一是**降低網路成本**。例如更好的動態頻譜/波束/睡眠管理，讓電費、站點維運、人力派工下降。如果只是增加 GPU 電費，那就不合格。

二是**創造企業收入**。例如智慧製造的即時視覺推論、低延遲影像分析、無人載具調度、企業私有 AI gateway。台灣大已把企業 AI、雲與資安列為成長方向，這和 AI-RAN 有戰略連接點。([台灣大哥大][3])

三是**提高戰略控制權**。如果未來端側 AI、機器人、AR 眼鏡、車聯網需要本地推論節點，台灣大不能只當 dumb pipe。但控制權不等於每個基站都裝 Nvidia；控制權來自 API、企業客戶關係、SLA、資料治理、邊緣平台與多供應商架構。

## 我會怎麼做：三階段打法

**第一階段：12 個月內，只做實驗與架構準備。**
成立 AI-RAN task force，但預算上限要小，重點是測試 Nokia/Nvidia、Ericsson、Samsung、雲商與白牌 Open RAN/Cloud RAN 的可替代性。避免一開始被單一 vendor 鎖死。KPI 包括 RAN latency、GPU utilization、每次推論成本、能耗、故障隔離、RAN workload 與 AI workload 共存時的穩定性。

**第二階段：選 3–5 個高價值場域做商用 PoC。**
我會優先選新竹科學園區、台中精密機械/製造聚落、高雄港或大型醫療/交通場域。這些地方企業客戶願意為 SLA、資安、低延遲、資料不出場付費。不要先做一般消費者市場，因為消費者 ARPU 不足以支撐 AI-RAN capex。

**第三階段：只有在收入模型成立後才擴張。**
若每個 AI-RAN/edge cluster 能綁到企業長約，並且毛利率高於傳統連線服務，才擴大。否則保留能力，不追逐設備商 roadmap。

## 「平價穩定傳輸」與「無處不在算力」不是二選一

真正的答案是：**電信商的底座必須永遠是平價穩定傳輸，但成長選擇權來自可控的邊緣算力。**

台灣大哥大不該把自己重新定義成 Nvidia GPU reseller，也不該只做低毛利 bit pipe。最好的定位是：

**可信連線 + 分散式邊緣平台 + 企業 AI/資安/雲服務整合商。**

這樣做有三個好處：

第一，保護現金流。5G capex 才剛進入緩和期，不應再用全網汰換把自由現金流打掉。

第二，保留未來話語權。透過小規模 AI-RAN、MEC、5G SA、network slicing 和 API，台灣大可以卡位未來邊緣 AI，而不是等雲商或設備商定義市場。

第三，避免「繳保護費」。跟 Nokia/Nvidia 合作可以，但合約要設計成可退出、可比較、可多供應商替代。我的原則會是：**買能力，不買信仰；買選擇權，不買鎖定。**

## 最終決策

作為 CTO，我會向董事會建議：

**不批准全網級 AI-RAN 汰換。批准有限、分區、企業收入導向的 AI-RAN/edge AI 投資組合。**

預算分配上，我會把大頭放在 RAN 自動化、5G SA/切片、MEC 平台、企業 AI/資安解決方案；AI-RAN 硬體只占小比例，用來取得學習曲線和供應商談判籌碼。

一句話：

**台灣大哥大不應該放棄「平價穩定的傳輸」，因為那是現金流護城河；但也不能錯過「在關鍵場域提供算力」的機會，因為那是下一代企業電信的定價權。**

Question 2:

題目二：IOWN 全光網路——解決「能耗黑洞」的終極救贖？
【題目說明】
隨著 AI 運算需求噴發，數據中心的能耗已成電信業者的噩夢。NTT 推出的 IOWN（全光與無線網路）技術，號稱能實現低能耗、高帶寬與低延遲。

衝突點： IOWN 是一套全新的體系，這意味著台灣大必須汰換現有設備。

請解題： 你會建議台灣大採取「引領者」策略，現在就加入 IOWN 嗎？還是選擇「追隨者」，未來再加入？如果是後者，你會建議在何種客觀條件達成下，再加入？

-----------------------------------------------------------------------------------------------------------

Suggestion 2:

我的建議會是：

**台灣大哥大不應該現在就採取「引領者」策略全面加入 IOWN；應該採取「策略性追隨者」：加入論壇或技術工作組、做小型 PoC、保留互通能力，但不做大規模汰換。真正導入要等到幾個客觀條件同時成熟。**

原因很簡單：**IOWN 的方向是對的，但現在還不是台灣大用股東資本大規模押注的時點。**

---

## 一、第一性原理：IOWN 解的是「資料搬移成本」，不是單純頻寬問題

AI 時代的能耗黑洞，很多人以為來自 GPU 本身，但從系統角度看，另一個巨大成本是：

**資料在 GPU、記憶體、交換器、資料中心、城市、國家之間搬來搬去。**

傳統網路架構中，光訊號經常要轉成電訊號處理，再轉回光訊號傳輸。每一次 O/E/O 轉換都帶來能耗、延遲、設備成本與故障點。IOWN 的核心想法，是把更多路徑改成 end-to-end photonics，用全光網路降低延遲、提高頻寬、減少功耗。NTT/IOWN Global Forum 對 APN，也就是 All-Photonics Network 的定位，就是面向超高容量、超低延遲與低功耗的新一代基礎設施。([NTT][1])

所以 IOWN 不是「更快的傳輸設備」而已，它更像是未來分散式 AI 資料中心、遠端 GPU、跨區同步運算、沉浸式媒體、金融低延遲交易的底層架構。

問題是：**台灣大哥大今天是否已經有足夠多的高價值 workload，需要為此重做網路？**

我的判斷是：還沒有。

---

## 二、為什麼不建議當「引領者」？

### 1. IOWN 仍處於早期商用與 PoC 擴張階段

NTT 的 IOWN 1.0 已在 2023 年推出，主要聚焦 APN 超低延遲服務；後續 roadmap 才逐步走向 board-to-board、chip-to-chip、甚至更深層的 photonic computing。([NTT][2]) IOWN Global Forum 也在推動 APN 用例、PoC 與 early adoption，例如多資料中心金融基礎設施、遠端媒體製作與串流。([IOWN Global Forum][3])

這代表它**不是空想**，但也還不是像 100G/400G Ethernet、DWDM、IP/MPLS 那樣成熟、標準化、供應商充分競爭的基礎建設。

對台灣大來說，現在 all-in 的風險是：你花的是成熟基礎建設的錢，買到的卻是早期生態系的折舊風險。

---

### 2. 台灣大目前更需要保護現金流，而不是啟動另一輪大規模汰換

台灣電信業剛走過 5G 投資高峰，資本市場目前更看重自由現金流、整併綜效、企業服務成長，而不是再開一輪大型網路重建。台灣大 2025 年現金 capex 已高於原先 guidance，公司在法說資料中也需要解釋 capex 現金流出增加的原因。([台灣大哥大][4])

所以 CTO 的責任不是追最新技術，而是問：

**這筆 capex 能不能在可預測時間內變成收入、成本節省或戰略控制權？**

目前 IOWN 很難直接回答這題。

---

### 3. 台灣市場規模不足以支撐「單獨當先行者」的成本

日本 NTT 推 IOWN，有它自己的條件：龐大的固網、資料中心、企業客戶、研發能量、國家級產業政策與跨國輸出企圖。台灣大哥大不具備同樣規模。

台灣大若當引領者，很可能變成：

**替供應商與標準陣營支付早期學習成本，但無法取得相應的全球定價權。**

除非台灣大能把 IOWN 變成企業服務或跨境資料中心服務的明確產品，否則它只是「技術領先」，不是「商業領先」。

---

## 三、但也不能完全不碰：台灣的能源問題會讓 IOWN 變重要

不當引領者，不代表忽視 IOWN。

台灣 AI 與半導體需求正在推升電力壓力。2026 年已有報導指出，AI 資料中心與半導體產業可能使台灣到 2030 年增加超過 5GW 電力需求。([Tom's Hardware][5]) 台灣也在推動「AI Island」相關政策，資料中心與算力基礎設施會持續成長，但能源供給、電網與冷卻都會成為限制因素。([Tom's Hardware][6])

這正是 IOWN 的戰略價值：
**它可能不是今天省錢最多的技術，但可能是未來 AI 基礎設施受電力約束時的解法之一。**

因此我的策略會是：

**不做全面導入，但要提早卡位。**

---

## 四、我會建議台灣大採取「策略性追隨者」

具體做法是三件事。

第一，**加入 IOWN Global Forum 或至少參與其技術/商業工作組**。這不是為了立刻採購，而是為了掌握 roadmap、互通標準、PoC 案例與供應商名單。IOWN Global Forum 目前正與 Telecom Infra Project 合作推動開放光網路技術，這代表它有往更開放、更可互通方向發展的企圖。([IOWN Global Forum][7])

第二，**不汰換現網，只在新建資料中心互連或企業專案中預留 APN-ready 架構**。例如新資料中心、AI cloud 節點、5G MEC 節點、國際海纜落地站、企業專網園區，可以要求新設備支援未來 APN/高速光互連演進，但不為了 IOWN 去拆掉仍可用的現有設備。

第三，**選一個台日跨境場景做 PoC**。這點很重要，因為中華電信已經和 NTT、Accton/Edgecore 展示台日跨境分散式 AI data center 與 remote GPU over APN 的應用。([Edgecore][8]) 台灣大不能在這條路線完全缺席，否則未來企業跨境 AI、金融、媒體、製造供應鏈場景會被競爭者先定義。

---

## 五、什麼條件達成後，才應該正式加入並擴大投資？

我會設定五個客觀門檻。

### 條件一：標準與供應商生態成熟

不是只有 NTT 或單一陣營能供貨，而是至少有多家設備商、光模組商、交換器商、控制器平台可互通。IOWN 若仍高度依賴單一 vendor roadmap，台灣大不應大規模導入。

**觸發點：**
APN 相關設備通過多供應商互通測試，並能與既有 DWDM、IP/MPLS、DCI 架構共存。

---

### 條件二：單位能耗節省能被審計證明

IOWN 最大賣點是低能耗，但 CTO 不能接受簡報式節能。

我會要求：

**在台灣大自己的 traffic profile 下，端到端每 bit 能耗至少下降 30%–50%，且包含光電轉換、冷卻、備援、控制平面與維運成本。**

若只看單一實驗室鏈路節能，不算。

---

### 條件三：有明確付費客戶，而不是只有技術展示

正式導入前，必須有企業客戶願意簽約，例如：

金融業跨資料中心同步、半導體供應鏈資料交換、AI 訓練資料搬移、遠端 GPU、醫療影像、媒體製作、智慧製造。

**觸發點：**
至少有 2–3 個企業客戶簽下多年合約，足以覆蓋專案 capex 與維運成本。

---

### 條件四：台灣大自身 AI/IDC 業務規模達到臨界點

如果台灣大的 AI cloud、IDC、MEC、企業雲業務還不夠大，IOWN 就只是高級管線。

**觸發點：**
當台灣大的資料中心互連流量、AI workload、企業專網/MEC 收入成長到現有承載網開始成為瓶頸，才值得升級。

換句話說，不是「先蓋 IOWN 等需求」，而是「需求已經逼近天花板，再用 IOWN 打開下一層」。

---

### 條件五：競爭者已開始商品化，而不是只有展示

中華電信與 NTT 的合作是重要觀察指標。如果競爭者把 IOWN/APN 包裝成企業級產品並開始取得金融、AI data center、跨境製造客戶，台灣大就不能再只是旁觀。

**觸發點：**
市場上出現可比較的商用標案、價格、SLA、節能數據與客戶續約案例。

---

如果我是台灣大 CTO，我會這樣對董事會說：

**IOWN 是正確方向，但不是現在全面汰換的理由。台灣大應採取「策略性追隨者」：現在加入觀察與 PoC，不做全網改造；等標準成熟、節能被審計、企業客戶願意付費、台灣大自身 AI/IDC 流量達臨界點，再分階段導入。**

一句話總結：

**IOWN 可能是 AI 能耗黑洞的長期解方，但現在對台灣大來說，它應該被視為「未來能源效率的選擇權」，不是今天立刻砸錢汰換網路的主航道。**

Question 3:

題目三：6G 的生存遊戲——如何終結「技術升級、毛利下降」的魔咒？
【題目說明】
2030 年 6G 時代即將來臨，但現實是殘酷的：全球 5G 的投資回收期比想像中漫長，且消費者對 5G 的溢價支付意願正在遞減。

衝突點： 6G 代表更頻密的基站建設、更驚人的投資，但如果商業模式仍停留在「平價吃到飽」，電信業獲利勢必大幅衰退。

請解題： 請思考：在 6G 時代，台灣大該如何突破困境？

-----------------------------------------------------------------------------------------------------------

Suggestion 3:

我的解法會很直接：

**台灣大不能把 6G 當成「5G 的下一次加速版」來投資。6G 若仍用吃到飽月租回收，必敗。台灣大必須把 6G 定義成「可編程的企業基礎設施」，讓網路能力變成可計價的產品，而不是繼續賣流量。**

也就是說，6G 的核心不是更快，而是：

**從賣 GB，轉成賣 SLA、API、邊緣算力、資安信任、產業解決方案。**

---

## 一、先承認殘酷現實：6G 不會自動帶來 ARPU 奇蹟

6G 標準化還在路上。3GPP 已規劃 Release 20 做 6G study，Release 21 才會進入 6G normative work，IMT-2030 相關完整系統定義預計在 2030 前後提交。([3GPP][1]) GSMA 也預期 6G 商用部署大約從 2030 年開始，但同時指出 6G 可能需要比今天多達三倍的頻譜資源來滿足資料需求。([GSMA][2])

這代表一件事：**6G 的成本壓力幾乎確定存在，但收入增量不確定。**

5G 已經給過教訓：消費者願意為「更快網速」付出的溢價有限；當競爭者都升級後，速度很快會變成基本配備，最後又回到價格戰。

所以台灣大在 6G 時代要先立一條鐵律：

**沒有新商業模式，就不做全網激進升級。**

---

## 二、第一性原理：電信網路真正可收費的不是速度，而是「確定性」

消費者買的是「能用、穩定、便宜」。
企業買的是「不能出錯、可保證、可整合、可稽核」。

所以 6G 的定價權不應來自 peak speed，而應來自五種確定性：

**延遲確定性、頻寬確定性、定位確定性、資安確定性、服務可用性確定性。**

這才是 6G 可以終結「技術升級、毛利下降」魔咒的關鍵。

如果台灣大只賣「6G 吃到飽 999 元」，那 6G 會重演 5G。
如果台灣大賣的是「工廠機器視覺 99.99% SLA」、「醫療影像低延遲專線」、「金融交易備援切片」、「AI 機器人園區網路」、「防詐身分驗證 API」，那 6G 才可能變成高毛利基礎設施。

---

## 三、台灣大的突破方向：從 Telco 變成 Tech-Telco，不只是口號

台灣大其實已經有正確方向。公司 2025 年公開表示，企業服務目標年增 20%，其中 cloud and AI 營收預期年增 223%，cybersecurity solutions 預期年增 94%。([台灣大哥大][3]) 這代表台灣大的成長點已經不只是傳統行動門號，而是企業 AI、雲、資安、整合服務。

6G 應該服務這個方向，而不是反過來讓公司再陷入基站 capex 黑洞。

我會把 6G 戰略拆成四個收入引擎。

---

## 四、第一個收入引擎：Network API，把網路能力賣給開發者

6G 時代，台灣大不能只把網路賣給終端用戶，還要賣給應用開發者、金融業、電商、遊戲、AI 服務商、物流平台。

GSMA Open Gateway 正在推動標準化 network APIs，目標是讓開發者能用一致方式取得電信網路能力。GSMA Intelligence 2025 年資料顯示，已有 73 個 operator groups 承諾參與，覆蓋接近全球 80% 行動用戶，2025 年重點轉向商用化與 monetisation。([GSMA Intelligence][4])

台灣大應該優先商品化這些 API：

**身分驗證 API**：防詐、金融登入、電商風控。
**SIM swap API**：銀行防止帳號盜用。
**位置驗證 API**：物流、保險、智慧城市。
**QoD / Quality on Demand API**：遊戲、直播、遠距醫療、AR/VR 臨時升級網路品質。
**裝置狀態 API**：IoT、車隊、企業資產管理。

這是 6G 最重要的商業邏輯之一：

**不要只向用戶收月租，而是向每一次「網路能力被調用」收費。**

這會讓台灣大從 subscription business 走向 usage-based platform business。

---

## 五、第二個收入引擎：企業專網與產業 SLA

6G 不應先打消費市場，而應先打企業場域。

台灣的優勢產業很清楚：半導體、電子製造、精密機械、醫療、港口、物流、智慧城市、資安與金融。這些產業不缺頻寬，缺的是可保證的無線基礎設施。

台灣大應該把 6G 包裝成「產業作業系統」：

**智慧工廠 6G package**：低延遲專網、機器視覺、AGV/AMR 調度、資安監控。
**醫療院區 package**：低延遲影像、行動護理、設備定位、資料不出院區。
**港口/物流 package**：無人車、吊車遠控、貨櫃追蹤、邊緣 AI。
**金融備援 package**：雙路徑低延遲、災備、身分驗證 API、資安 SOC。

重點是不要賣「6G 連線」，而是賣「一個可運作的產業成果」。

---

## 六、第三個收入引擎：邊緣 AI，不做雲商的搬運工

6G 會和 AI、感測、定位、邊緣運算綁在一起。台灣大如果只是幫雲商接最後一哩，那毛利會被雲商吃掉。

正確做法是建立自己的 **Telco Edge AI 平台**：

1. 在都會核心節點與企業園區部署邊緣算力。
2. 與 6G slicing、低延遲網路、資安、資料治理整合。
3. 對企業賣「推論結果」或「SLA」，而不是單純賣 GPU 時數。
4. 和公有雲合作，但保留客戶介面與資料治理主導權。

台灣不缺 AI 供應鏈需求。台灣正在推 AI Island 政策，目標強化算力與 AI 基礎設施；同時，資料中心與 AI 基礎設施也面臨能源與電網挑戰。([Tom's Hardware][5]) 這對台灣大反而是機會：它可以把 6G、IDC、MEC、資安和企業服務包成一個可信邊緣平台。

---

## 七、第四個收入引擎：資安與信任，這是電信商最自然的高毛利產品

在 AI 詐騙、深偽、身份盜用、IoT 攻擊普及後，電信商最大的資產不是頻譜，而是：

**SIM、號碼、位置、裝置、網路行為、帳務關係、KYC 信任鏈。**

台灣大應該在 6G 前就開始把這些能力產品化：

**企業零信任連線**、**防詐 API**、**裝置身分管理**、**IoT 安全連線**、**企業行動端點風險評分**、**AI bot / human verification**。

這些服務不需要等 6G 才做，但 6G 可以讓它們更即時、更細緻、更可保證。

---

## 八、投資策略：6G 不全網豪賭，而是「需求牽引式部署」

台灣大應採取三階段策略。

### 第一階段：2026–2028，先把 5G Advanced 榨乾

不要急著喊 6G。先把 5G SA、network slicing、MEC、Open Gateway API、企業專網、自動化維運做好。

這一階段的目標是：

**先證明企業願意為確定性付費，再決定 6G 投資規模。**

如果 5G SA slicing 都賣不動，6G slicing 也不會突然成功。

---

### 第二階段：2028–2030，只在高價值區域做 6G pre-commercial

優先部署地點不應是全台平均鋪開，而是：

新竹科學園區、竹科/中科/南科供應鏈、台北金融核心、高雄港、桃園機場、醫療園區、大型展演場館、AI data center 周邊。

這些地方有明確企業收入與 SLA 需求，能支撐較高 capex。

---

### 第三階段：2030 後，根據收入密度擴張

6G 不應以「人口覆蓋率」作為唯一 KPI，而應增加三個新 KPI：

**每 MHz 企業收入**
**每基站 API 調用收入**
**每平方公里 SLA 合約收入**

只要 KPI 還是「覆蓋率、下載速度、用戶數」，台灣大就會回到老路。
KPI 改了，投資邏輯才會改。

---

## 九、定價模式也必須改

6G 時代不能只有吃到飽。台灣大應該保留平價消費者方案，但高毛利要靠分層定價。

我會設計四層：

**第一層：基本連線**
一般消費者吃到飽，控制成本，不追求高毛利。

**第二層：體驗型加價**
遊戲、直播、AR、影音創作者可臨時購買低延遲或上傳保證。

**第三層：企業 SLA**
企業按場域、裝置數、延遲、可靠度、安全等級付費。

**第四層：API 與平台抽成**
金融、電商、遊戲、AI 應用按 API call、成功驗證、品質保證次數付費。

這樣台灣大才不會把 6G 的全部成本壓在消費者月租上。

---

## 十、最終答案：台灣大的 6G 生存策略

我會給台灣大三句戰略原則：

**第一，6G 不賣速度，賣確定性。**
速度會被競爭吃掉，SLA 才能收費。

**第二，6G 不先全網鋪，先鋪高收入密度場域。**
哪裡有企業願意付費，哪裡先部署。

**第三，6G 不只是網路升級，而是企業平台升級。**
要和 AI、雲、資安、API、MEC、產業解決方案綁在一起。

所以我的結論是：

**台灣大要突破「技術升級、毛利下降」的魔咒，就不能再把 6G 當成消費者網速戰。它必須把 6G 變成企業可編程基礎設施，用 Network API、企業 SLA、邊緣 AI、資安信任來重建定價權。**

一句話：

**6G 的勝負不在誰網速最快，而在誰能把網路能力包裝成企業願意持續付費的生產力。**

最後的建議

## 戰略主軸

台灣大未來 10 年的發展主軸應是：

> **守住平價穩定連線的現金流，用 API、SLA、邊緣 AI、資安信任與企業場域服務，創造第二成長曲線。**

換句話說，消費者市場繼續追求**低成本、高穩定、高留存**；企業市場則轉向**高毛利、高 SLA、高整合度**。

# 三、Phase 1：2026–2027

## 目標：先把 5G 變成會賺錢的平台，不急著追 6G

這兩年最重要的任務不是導入最炫的技術，而是建立 6G 前的商業底座。

## 1. 技術執行方針

**第一，完成 5G SA、MEC、network slicing 的商用基礎。**
如果 5G slicing、MEC、低延遲 SLA 在 2026–2027 還沒有形成可賣產品，6G 來了也不會自動變現。

**第二，建立 Network API 平台。**
GSMA Open Gateway 已有 73 個 operator groups 承諾參與，覆蓋接近全球 80% 行動用戶，2025 年重點轉向 API 商用化與變現。台灣大應優先導入 SIM swap、number verification、location verification、Quality on Demand、device status 等 API。([GSMA Intelligence][2])

**第三，導入 AI for Network，而不是先大規模 AI-RAN。**
先做 AI 節能、流量預測、自動化派工、RAN 異常偵測、容量規劃。這些能直接降低 OPEX，不需要全面汰換基站。

**第四，建置企業級 edge cloud 最小可行平台。**
先在台北、新北、桃園、新竹、台中、高雄建立區域 edge nodes，不做每個基地台都放 GPU 的重資本部署。

## 2. 商業執行方針

台灣大要在這階段推出三種新產品：

**Network API 收費產品**
賣給銀行、電商、遊戲、物流、保險、資安公司。

**企業 SLA 連線產品**
不是賣「5G 專線」，而是賣「低延遲保證」、「高可用保證」、「資料不出場域」。

**企業資安信任產品**
把 SIM、號碼、位置、裝置狀態、網路行為變成防詐與零信任服務。

## 3. KPI

2027 年底前應達成：

| KPI                  |          目標 |
| -------------------- | ----------: |
| Network API 付費客戶     |     30–50 家 |
| 企業 SLA / 私網專案        |      10 個以上 |
| AI 維運節省 OPEX         |        5–8% |
| MEC / Edge AI 付費 PoC |       5 個以上 |
| 消費者網路 CAPEX 強度       | 不因新技術試點明顯上升 |

# 四、Phase 2：2028–2029

## 目標：把 AI-RAN、IOWN、Edge AI 從技術展示變成企業收入

這階段是關鍵轉折點。台灣大要開始試點 AI-RAN 與 IOWN，但仍然不能全網導入。

---

## 1. AI-RAN 策略：只做高價值場域，不做全網換代

Nvidia/Nokia AI-RAN 代表未來方向，但台灣大應把它當成「選擇權」，不是「主航道」。Nvidia 與 Nokia 的合作目標是把 Nokia RAN 軟體跑在 Nvidia AI 平台上，形成 AI-native 5G-Advanced/6G 網路。這很重要，但也意味著供應商鎖定與 CAPEX 壓力會上升。([NVIDIA Newsroom][1])

## AI-RAN 執行場域

優先選擇：

| 場域      | 用例                |
| ------- | ----------------- |
| 新竹科學園區  | 智慧製造、機器視覺、低延遲資料交換 |
| 中科 / 南科 | 半導體供應鏈、AGV、工廠 AI  |
| 高雄港     | 無人載具、吊車遠端操控、貨櫃追蹤  |
| 醫療院區    | 醫療影像、院內定位、資料不出院   |
| 大型場館    | 即時影像、AR 服務、安防分析   |

## AI-RAN 投資門檻

只有符合以下條件才擴大：

| 條件                    | 門檻               |
| --------------------- | ---------------- |
| 每站新增收入                | 能覆蓋新增折舊與電費       |
| GPU / accelerator 使用率 | 穩定達 40–50% 以上    |
| 對 RAN KPI 改善          | 明確降低延遲或提升容量效率    |
| 企業合約                  | 至少 3 年期 SLA 合約   |
| 供應商架構                 | 不被單一 vendor 完全鎖死 |

---

## 2. IOWN / 全光網策略：策略性追隨者

IOWN 的方向正確，因為 AI 時代真正的瓶頸之一是資料搬移能耗。IOWN Global Forum 的 All-Photonics Network 強調高容量、超低延遲與節能，並以減少電處理來降低網路能耗。([IOWN Global Forum][3])

但台灣大不應在 2028–2029 全面汰換承載網，而應採取：

**加入生態、做 PoC、新建節點預留 APN-ready，不拆舊網。**

## IOWN PoC 場景

| 場景                     | 目的                                    |
| ---------------------- | ------------------------------------- |
| 台北—新竹 AI data corridor | 驗證低延遲資料中心互連                           |
| 台灣—日本跨境企業服務            | 卡位台日 AI / 製造 / 金融資料交換                 |
| 金融雙活資料中心               | 驗證低延遲、高可靠 DCI                         |
| AI GPU pool 遠端使用       | 測試 remote GPU / distributed inference |

## IOWN 擴大導入條件

只有當以下條件達成，才進入正式投資：

| 條件   | 客觀門檻                          |
| ---- | ----------------------------- |
| 節能   | 每 bit 能耗下降 30–50%，且經第三方審計     |
| 標準成熟 | 多供應商互通，不依賴單一陣營                |
| 企業收入 | 至少 2–3 個大型企業願意簽多年合約           |
| 網路瓶頸 | 現有 DCI / IP / DWDM 成為 AI 業務瓶頸 |
| 競爭態勢 | 對手開始商用並取得大型客戶                 |

---

## 3. 商業執行方針

2028–2029 年，台灣大應推出「企業場域包」：

| 產品包              | 內容                          |
| ---------------- | --------------------------- |
| 智慧工廠包            | 私網、MEC、AI 視覺、資安、SLA         |
| 金融信任包            | SIM swap API、位置驗證、低延遲備援、SOC |
| 醫療院區包            | 私網、低延遲影像、IoT 設備管理、資料治理      |
| 港口物流包            | 低延遲連線、定位、邊緣 AI、車隊管理         |
| AI data corridor | DCI、APN PoC、edge GPU、資安連線   |

---

# 五、Phase 3：2030–2031

## 目標：6G 不全網豪賭，只做高收入密度部署

2030 前後，6G 會逐步進入商用視窗。但台灣大不能用 5G 思維做 6G。

3GPP 目前規劃 Release 20 做 6G studies，Release 21 才開始正式 6G normative work；因此 2030 前後的 6G 應視為「高價值場域優先」而不是「全台覆蓋優先」。([3GPP][4])

---

## 1. 6G 部署原則

**原則一：不以人口覆蓋率作為第一 KPI。**
6G 第一 KPI 應是收入密度，不是覆蓋率。

**原則二：先企業，後消費者。**
消費者市場不會為 6G peak speed 支付足夠溢價。

**原則三：6G 賣的是確定性，不是速度。**
低延遲、可靠度、定位、感測、資安、SLA 才是定價權。

---

## 2. 優先部署區域

| 優先級 | 區域          | 理由                 |
| --- | ----------- | ------------------ |
| 1   | 新竹科學園區      | 半導體、智慧製造、高價值企業 SLA |
| 1   | 台北金融核心      | 防詐、低延遲、金融 API      |
| 1   | 高雄港 / 桃園機場  | 物流、自動化、關鍵基礎設施      |
| 2   | 中科 / 南科     | 工業 AI、私網、供應鏈       |
| 2   | 醫療中心        | 低延遲影像、資料治理         |
| 3   | 大型展演 / 體育場館 | AR、即時影像、臨時 QoS     |

---

## 3. 6G 商業模式

台灣大要避免「6G 吃到飽 999 元」這種自殺式產品。應採四層定價：

| 層級     | 對象           | 收費方式                  |
| ------ | ------------ | --------------------- |
| 基本連線   | 一般消費者        | 月租、成本控制               |
| 體驗加值   | 遊戲、直播、創作者    | 臨時 QoS、低延遲加購          |
| 企業 SLA | 工廠、醫療、金融、物流  | 場域合約、裝置數、SLA          |
| API 平台 | 銀行、電商、AI 應用商 | API call、成功驗證、QoD 使用量 |

---

## 4. 新 KPI

6G 時代台灣大應改用以下 KPI：

| 舊 KPI | 新 KPI                                         |
| ----- | --------------------------------------------- |
| 人口覆蓋率 | 每平方公里 SLA 收入                                  |
| 下載速度  | 可保證延遲達成率                                      |
| 每用戶流量 | 每 API call 收入                                 |
| 基站數量  | 每站企業毛利                                        |
| ARPU  | ARPA：Average Revenue per Account / API / Area |

---

# 六、Phase 4：2032–2035

## 目標：成為台灣可信 AI 邊緣平台

到 2032–2035，台灣大應該完成角色轉換：

> 從 mobile operator 變成 **Trusted Connectivity + Edge AI + Cybersecurity + Network API Platform**。

---

## 1. 技術架構目標

2035 年的台灣大目標架構應是：

| 層級            | 能力                                                       |
| ------------- | -------------------------------------------------------- |
| Access        | 5G-A / 6G、Wi-Fi、private network、IoT                      |
| Transport     | IP / DWDM / APN-ready optical network                    |
| Edge          | 都會 edge cloud、企業 edge appliance、AI inference pool        |
| Platform      | Network API、SLA orchestration、billing、developer portal   |
| Trust         | SIM identity、device identity、zero trust、fraud prevention |
| Industry Apps | 工廠、金融、醫療、物流、智慧城市                                         |

---

## 2. 平台化產品

到 2035，台灣大應有五條主要收入線：

| 收入線         | 說明                   |
| ----------- | -------------------- |
| 消費者連線       | 穩定現金流，控制 CAPEX       |
| 企業 SLA 網路   | 私網、切片、低延遲、高可靠        |
| Network API | 防詐、身分、位置、QoD、裝置狀態    |
| Edge AI     | 推論服務、資料治理、低延遲 AI     |
| 資安信任        | 零信任、SOC、IoT 安全、AI 防詐 |

---

# 七、具體組織與執行方針

技術藍圖若沒有組織改造，會變成簡報。台灣大需要同步做五項組織調整。

---

## 1. 成立「Network Platform Business Unit」

不要讓 API、MEC、slicing、企業私網分散在不同部門。應成立一個橫跨網路、企業業務、資安、雲端、產品的 BU。

負責：

| 任務              | 說明                                         |
| --------------- | ------------------------------------------ |
| Network API 商品化 | API catalog、定價、開發者入口                       |
| SLA 產品          | 定義 latency、availability、jitter、security 等級 |
| Edge AI 平台      | 算力、模型部署、資料治理                               |
| 企業場域整合          | 工廠、港口、醫療、金融方案                              |
| 統一帳務            | API、SLA、算力、連線整合計費                          |

---

## 2. CAPEX Governance：建立「技術投資紅綠燈」

任何 AI-RAN、IOWN、6G 投資都必須通過紅綠燈審查。

| 燈號 | 條件                       | 行動                  |
| -- | ------------------------ | ------------------- |
| 綠燈 | 有企業合約、有節能數據、有多供應商選擇      | 擴大部署                |
| 黃燈 | 技術有潛力但商業未驗證              | PoC / limited trial |
| 紅燈 | 只有 vendor roadmap、沒有收入模型 | 不投資                 |

---

## 3. Vendor Strategy：避免再次「繳保護費」

對 Nokia/Nvidia、NTT/IOWN、雲商、設備商都採取同一原則：

**合作，但不鎖死。**

執行要點：

| 方針             | 內容               |
| -------------- | ---------------- |
| Multi-vendor   | 至少兩家設備商可替代       |
| Open API       | 所有平台能力必須 API 化   |
| Exit clause    | 合約要有退出與價格重談機制    |
| Benchmark      | 每年做成本、能耗、效能比較    |
| Data ownership | 企業資料與網路資料主權留在台灣大 |

---

## 4. 人才策略：從 RF 工程師擴展到 AI / Cloud / API 工程師

未來 10 年電信 CTO 最缺的不是會蓋基站的人，而是能把網路產品化的人。

人才配置應轉向：

| 人才                            | 任務                                    |
| ----------------------------- | ------------------------------------- |
| Cloud native network engineer | 5G core、6G core、Kubernetes、automation |
| AI operations engineer        | RAN AI、能耗最佳化、異常偵測                     |
| API product manager           | Network API 商品化                       |
| Edge AI architect             | 企業推論平台、資料治理                           |
| Cybersecurity architect       | 零信任、防詐、IoT 安全                         |
| Industry solution architect   | 半導體、醫療、金融、物流場域方案                      |

# 八、年度重點 Roadmap

|   年度 | 主要任務                                                    |
| ---: | ------------------------------------------------------- |
| 2026 | 完成 5G SA / MEC 商用底座；啟動 Network API 平台；AI for Network 導入 |
| 2027 | 推出防詐 API、SIM swap API、QoD API；完成 10 個企業 SLA 專案          |
| 2028 | AI-RAN 在 3 個高價值場域 PoC；IOWN/APN 做台北—新竹或台日 PoC            |
| 2029 | Edge AI 平台商品化；智慧工廠、金融信任、醫療院區產品包成形                       |

| 2031 | 6G + slicing + API + Edge AI 整合商品化；不做全網鋪設               |
| 2032 | 擴大企業 6G 場域；APN-ready optical network 部署於高流量 DCI         |
| 2033 | Network API 成為穩定收入線；企業 SLA 收入明顯成長                       |
| 2034 | Edge AI 與資安信任服務平台化；跨境 AI data corridor 成熟               |
| 2035 | 台灣大完成 Tech-Telco 轉型，成為可信 AI 邊緣基礎設施商                     |

# 九、最終策略結論

台灣大未來 10 年不應在 AI-RAN、IOWN、6G 三條線上全面豪賭，而應採取以下組合策略：

| 技術          | 策略                              |
| ----------- | ------------------------------- |
| AI-RAN      | 高價值場域試點，企業合約牽引，不全網汰換            |
| IOWN / APN  | 策略性追隨者，加入生態、做 PoC，等節能與商業條件成熟再擴大 |
| 6G          | 不賣速度，賣 SLA、API、邊緣 AI、資安信任       |
| 5G-A        | 2026–2029 的真正變現主力               |
| Network API | 最優先商品化，建立平台收入                   |
| Edge AI     | 以企業場域為核心，不做雲商搬運工                |

一句話總結：

> **台灣大的 10 年藍圖，不是追逐每一個新技術名詞，而是把每一項技術都放進同一個商業邏輯：降低單位傳輸成本、提高企業定價權、建立可編程網路平台，最終從「平價連線商」升級為「可信 AI 邊緣基礎設施商」。**
